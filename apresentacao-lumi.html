04 • Arquitetura do Sistema

Arquitetura de Software: Padrão Serverless BFF

Desacoplamento estrito em 3 camadas para garantir isolamento de banco e segurança operacional.

🖥️ 1. Camada de Apresentação (PWA)

  • React 19 + TypeScript (tipagem 100% estrita).
  • Derivação de chaves e cifragem no navegador (Argon2id WASM + AES-256-GCM).
  • Zero comunicação direta com o banco: todo acesso passa pelo cliente HTTP api-client.ts.

⚡ 2. Backend-For-Frontend (BFF)

  • Vercel Serverless Functions padronizadas com Web Fetch API (Request / Response).
  • Rotas modulares sob /api/*: auth, ideias e perfil do usuário.
  • Autenticação stateless via Bearer Token JWT (HS256) e injeção do usuario_id.

☁️ 3. Persistência & IA Externa

  • TursoDB na borda com Hrana v2 (apenas o BFF detém as credenciais do banco).
  • Google Gemini REST direto do cliente usando a chave BYOK do usuário no header x-goog-api-key.

05 • Banco de Dados & Web Services

Persistência na Borda e Web Services RESTful

TursoDB via HTTP Pipeline v2 e endpoints serverless de alta performance e isolamento multitenant.

🗄️ TursoDB (Edge SQLite / Hrana v2)

  • Protocolo Hrana v2 sobre HTTPS: Comunicação rápida via HTTP Pipeline v2, dispensando binários nativos C/C++ ou @libsql/client pesado.
  • Isolamento Multi-inquilino: Todas as consultas de ideias são estritamente filtradas por usuario_id vinculado ao token JWT validado.
  • Criptografia em Repouso: Campos confidenciais são armazenados exclusivamente como ciphertext (AES-GCM) e credenciais como PHC Argon2id.
  • Schema Relacional Enxuto: Tabelas usuarios e ideias com chave estrangeira e integridade referencial.

🌐 Web Services Serverless (`/api/*`)

  • Auth Endpoints: /api/auth/registrar, /api/auth/login e /api/auth/sessao para ciclo de vida de autenticação.
  • CRUD de Ideias: GET /api/ideias (listar), POST /api/ideias (criar com E2E), PATCH (favoritar) e DELETE.
  • Configurações do Usuário: /api/usuario/config e /api/usuario/perfil para troca de modelo e sincronização de chaves cifradas.
  • Zero Vazamento de Segredos: Tokens de banco e Pepper ficam confinados nas variáveis do servidor Vercel.

Engenharia de IA: Prompts, Schemas e Integração REST

07 • Engenharia de Segurança

Segurança Criptográfica Zero-Knowledge

Matematicamente impossível para o servidor inspecionar os segredos dos usuários.

🔐 Argon2id (WebAssembly)

Algoritmo de ponta (vencedor do PHC). Executado no cliente consumindo 19 MiB de memória com 3 iterações. Gera hash PHC canônico com salt embutido (OWASP).

🛡️ HMAC-SHA256 Pepper

Segredo server-side injetado antes do hash. Impede ataques de dicionário e tabelas rainbow mesmo em caso de dump não autorizado do banco.

🔑 AES-256-GCM End-to-End

Chave de cofre de 256 bits derivada localmente. Chave Gemini, descrição da ideia e prompt são cifrados com IV aleatório de 96 bits por registro.

Fluxo E2E: Senha ➔ Pepper (HMAC) ➔ Argon2id ➔ vaultKeyHex ➔ AES-256-GCM (Ciphertext) ➔ TursoDB
