01 • Introdução & Problema

O Desafio Criativo e a Privacidade na Nuvem

Como gerar ideias originais com IA sem expor segredos industriais ou custos de infraestrutura.

⚡ O Bloqueio Criativo

Profissionais e estudantes frequentemente enfrentam dificuldades para estruturar ideias de novos aplicativos, conteúdos, modelos de negócios e ferramentas open source do zero.

🔒 Dilema da Privacidade

Ferramentas convencionais de IA na nuvem exigem envio de dados em texto claro para servidores de terceiros, comprometendo a propriedade intelectual de novas iniciativas.

💡 A Solução Lumi

Um PWA portátil e veloz que consome a IA de ponta do Google Gemini com Bring Your Own Key (BYOK) e banco de dados SQLite distribuído na borda, com isolamento e criptografia E2E.

02 • Arquitetura do Sistema

Arquitetura Serverless BFF (Backend-For-Frontend)

Separação estrita de camadas para garantir segurança e zero vazamento de credenciais.

🖥️ Cliente (PWA React 19)

  • UI Responsiva: Tailwind CSS v4, tokens de design e componentes shadcn/ui.
  • Portabilidade PWA: Service Worker com cache-first e manifest instalável.
  • Comunicação Unificada: Cliente nunca fala diretamente com o banco de dados; todas as operações trafegam via /api/*.
  • Zero Segredos no Browser: Tokens de banco e chaves de serviço ficam 100% blindados fora do bundle client-side.

☁️ BFF Serverless & TursoDB

  • Vercel Serverless Functions: Rotas /api/auth/*, /api/ideias e /api/usuario/* com Web Fetch API padrão.
  • TursoDB Edge Engine: Conexão ultra rápida via HTTP Pipeline v2 (protocolo Hrana v2 sobre HTTPS), dispensando dependências C nativas.
  • Proxy de Dev Vite: Interceptador dinâmico em desenvolvimento espelhando o comportamento de produção serverless.

03 • Engenharia de Segurança

Segurança Criptográfica Zero-Knowledge

O servidor armazena dados, mas é matematicamente incapaz de ler o conteúdo protegido.

🔐 Argon2id (WASM)

Derivação no navegador via WebAssembly (19 MiB RAM, 3 iterações). Gera hash no formato canônico PHC padrão OWASP e chave simétrica vaultKeyHex (256 bits).

🛡️ HMAC-SHA256 Pepper

Camada secreta adicional mantida no servidor para enriquecer a senha antes da derivação, inviabilizando rainbow tables e ataques de força bruta offline.

🔑 AES-256-GCM E2E

Chave Gemini e dados de ideias (descrição e tema) são cifrados no cliente com vetor de inicialização (IV) aleatório de 96 bits por registro. Ciphertext único sempre.

Fluxo E2E: Senha do Usuário ➔ Pepper (HMAC) ➔ Argon2id ➔ vaultKeyHex (256 bits) ➔ AES-256-GCM (Ciphertext) ➔ TursoDB

04 • Integração de IA

Google Gemini & Structured Outputs

Geração com garantia de tipagem estrita e conformidade de JSON schema.

🤖 Chamada REST Direta

  • Zero SDK Overhead: Chamadas REST puras diretamente ao endpoint oficial v1beta do Google AI Studio.
  • Chave no Header: Autenticação via header x-goog-api-key diretamente com a chave informada pelo usuário (BYOK).
  • Modelos de Alta Velocidade: Suporte nativo a gemini-2.5-flash, gemini-2.5-flash-lite, gemini-2.5-pro e gemma.

📋 Structured Outputs (JSON Schema)

  • Garantia de Esquema: Resposta estruturada com responseMimeType: "application/json".
  • Atributos Extraídos: Título atraente, descrição contextualizada e categoria classificada.
  • Sem Alucinações de Formato: Evita erros de parse no frontend, garantindo rendering estável e imediato.

07 • Conclusão & Próximos Passos

Conclusão do Projeto

Resultados alcançados e perspectivas futuras para a plataforma Lumi.

🎯 Objetivos Conquistados

  • Aplicação web moderna, responsiva e instalável (PWA).
